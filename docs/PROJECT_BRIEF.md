# Cucrobot — сводка проекта и роадмап

Документ для быстрого входа в проект: человеку или другой нейросети. Актуален на 2026-10-01.

## Что это

Telegram-бот на русском: пользователь кидает фото человека, выбирает киноактёра из каталога (или «своего героя» с любого фото) и получает через ~20 секунд совместное фото в одной из сцен. Монетизация: внутренняя валюта «кристаллики», пакеты за Telegram Stars, подписки через Tribute (СБП/карта) и Stars. Админы управляют каталогом и смотрят метрики прямо в боте и в мини-приложении.

- Репозиторий: https://github.com/dimasova04/Cucrobot (публичный)
- Прод: Railway, `https://cucrobot-production.up.railway.app` (health `/health`, вебхук Tribute `/webhooks/tribute`, мини-приложение `/app`)
- Бот работает в одном экземпляре (long polling), несколько реплик запускать нельзя.

## Границы продукта (не обсуждаются)

- Никакой эротики и раздевания. В каждый промпт добавляется `SAFETY_CLAUSE` («все одеты, одежда по сцене»), текст пользователя и описания админов проходят стоп-лист (`services/generation/content_filter.py`), у Runware включена проверка контента, помеченный результат не отправляется, кристаллики возвращаются.
- Только киноактёры и публичные люди не из порноиндустрии. Имена из порноиндустрии отклоняются при добавлении (`BLOCKED_ACTOR_NAMES` в `services/catalog.py`).
- Правила при `/start`: 18+, фото только с разрешения человека, ответственность на пользователе. Без принятия правил бот не работает.

## Стек

Python 3.12 (Docker) / 3.14 локально · aiogram 3 · SQLAlchemy 2 async + asyncpg (тесты на SQLite/aiosqlite) · Alembic · Redis для FSM (fallback память) · aiohttp (вебхук, мини-приложение, API) · Runware SDK (генерация) · OpenCV (проверка лица) · loguru · pytest (164 теста, `pytest -W error`).

## Сценарий пользователя

1. `/start` → правила → «Принимаю» → 3 кристаллика, меню-карточка с баннером и кнопками (Сделать фото, Профиль, Бонус, Как это работает, Кабинет).
2. «Создать фото» → одно фото (проверка лица) → список актёров (+ «🦸 Свой герой» с любого фото) → генерация сразу со случайной сценой.
3. Под результатом: «Новая фотосессия» (та же сцена, новый кадр), «Выбрать сцену» (каталог + «Своя сцена» текстом или фото места), «Другой актёр», «Ещё актёр», «Своя деталь» (до 100 символов; дорисовывает тот же кадр: предыдущее фото идёт референсом, seed фиксирован, меняется только деталь), «Скачать в HD» (оригинал файлом, ссылка живёт 7 дней), «Новое фото». Везде «◀️ Назад».
4. Профиль: баланс, подписка, бонус (кнопка, раз в 24 ч: 3 без подписки, 10 с подпиской), качество (обычное 1 💎 / премиум 3 💎, премиум только по подписке), пакеты и подписка.

## Экономика (все значения в env, см. `.env.example`)

| Что | Значение |
|---|---|
| Старт | 3 💎 |
| Бонус | 3 💎 / 24 ч; подписчику 10 💎 / 24 ч |
| Обычное фото | 1 💎 (Muse Image, ~$0.01) |
| Премиум фото | 3 💎 (Nano Banana 2, ~$0.05) |
| Пакеты | 50 / 100 / 300 💎 за 199 / 349 / 899 ⭐ |
| Подписки | неделя 290 ₽ / 229 ⭐ (+10 💎), месяц 590 ₽ / 469 ⭐ (+50 💎), 3 месяца 1290 ₽ / 999 ⭐ (+200 💎) |

Модели и размеры кадра задаются переменными `MODEL_BASE_AIR`, `MODEL_PREMIUM_AIR`, `MODEL_*_PORTRAIT/LANDSCAPE`. История: FLUX.2 klein (пластилиновые лица) → Seedream 4.5 (хорошо, $0.04, требует ≥3.69 Мпикс) → Muse Image (сейчас, $0.01, 1280×1920).

## Платежи

- **Stars:** инвойс из бота или из мини-приложения (`create_invoice_link` + `openInvoice`), начисление по `successful_payment`, идемпотентно по `telegram_payment_charge_id`.
- **Tribute:** одна подписка с тремя периодами, ссылка в `TRIBUTE_SUB_*_URL`, вебхук с HMAC-подписью по `TRIBUTE_API_KEY`; период берётся из вебхука; нераспознанный товар пишется как `unresolved` и досылается после правки id. Известный риск: Tribute может не присылать вебхук о продлении, тогда нужен парсер уведомлений из канала.
- Все начисления только через `services/billing/wallet.py` и `grants.py` (блокировка строки, защита от дублей и гонок).

## Админка и рефералы

Команды: `/admin` (список), `/stats`, `/user <id>`, `/give <id> <n>`, `/sub <id> <план>`, `/block`, `/unblock`, `/actors`, `/scenes`, `/ref_add <код> <partner_id|-> <название>`, `/refs`, `/ref_off`, `/ref_on`. Партнёр видит свою статистику по `/partner`. Меню «/» у админов расширенное, у остальных три команды. Мини-приложение: вкладка «Метрики» только для админов (итоги, приход за день/7/30 дней, график, таблица рефералов).

## Как запустить

```
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env            # BOT_TOKEN, RUNWARE_API_KEY, ADMIN_IDS
.venv/bin/python -m pytest -q -W error
.venv/bin/python main.py
```

Railway: сервис из репозитория (Dockerfile) + PostgreSQL + Redis; переменные из `.env.example`; `WEBAPP_URL=https://<домен>/app`. Пуш в `main` деплоит автоматически.

6. **Кэш каталога в памяти** (спека §4), сейчас списки читаются из БД на каждый запрос.
7. **Уведомление о готовом бонусе** раз в сутки тем, кто не заходил (мягко, с отпиской).
8. **Реф-выплаты:** экспорт `/refs` в CSV, история по месяцам.
9. **Мини-приложение:** вкладка «Мои фото» (история генераций с HD), выбор актёра и сцены прямо в приложении.
10. **Ops:** дашборд ошибок Runware, алерт при падении баланса Runware, `.env` для стейджа.

## Известные ограничения

- Telegram сжимает фото до 1280 px, оригинал только через «Скачать в HD».
- Оригиналы на Runware живут 7 дней.
- Стоп-лист ловит по словоформам; ложные срабатывания правятся точечно через списки исключений.
- Логи прода доступны только в панели Railway (CLI не настроен).
